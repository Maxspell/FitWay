# Ошибки гидратации React (Hydration Errors) в Next.js

Справочник по типичным причинам расхождения серверного HTML и клиентского DOM (Hydration Mismatch) и методам их устранения.

---

## 📌 Что такое ошибки гидратации (#418, #423)
В продакшен-бандлах React ошибки гидратации минифицируются:
* **Error #418**: Текст или структура в клиентском рендере не соответствуют тому, что пришло с сервера при SSR.
* **Error #423**: Общий сбой дерева гидратации React из-за расхождения структуры узлов.

---

## 🔍 Частые причины и кейсы в FitWay

### 1. Невалидная вложенность HTML-элементов (DOM Auto-Correction)
* **Проблема**: Размещение блочных элементов (`<div>`, `<section>`, списков или виджетов) внутри строчных или текстовых тегов, например `<p>`:
  ```html
  <!-- ОШИБКА -->
  <p>
    <div>Блочный виджет твита или видео</div>
  </p>
  ```
* **Почему возникает ошибка**: Браузерный HTML-парсер не допускает `<div>` внутри `<p>`. Он автоматически закрывает `<p>` перед `<div>` и открывает новый после него. Серверный же рендер Next.js отдает исходное дерево. При сопоставлении клиент видит другую структуру DOM и выбрасывает #418/#423.
* **Кейс с Twitter Embed**: В `ReactMarkdown` ссылки из статьи оборачивались в `<p>`. При замене ссылки на блочный виджет твита происходил сбой.
* **Решение**: Замена рендерера `<p>` в Markdown на тег `<div>` и использование блочных `<span>` внутри виджетов. Подробнее: [[bugs/twitter-embed-video-403-hydration]].

### 2. Динамические даты и часовые пояса
* **Проблема**: Использование функций форматирования дат с зависимостью от локали пользователя (`toLocaleDateString`) при SSR. Если на сервере таймзона UTC, а у клиента UTC+3, даты могут отличаться.
* **Решение**: Фиксация локали и таймзоны (например `en-US`), либо использование единых форматов. Подробнее: [[frontend/blog-date-sorting-metadata]].

### 3. Обращение к `window`, `localStorage` или cookie до монтирования
* **Проблема**: Проверка условий вроде `typeof window !== 'undefined'` в теле компонента на первом рендере.
* **Решение**: Перенос браузерных проверок и чтения хранилища внутрь хука `useEffect()`, либо использование `next/dynamic` с `{ ssr: false }`.
