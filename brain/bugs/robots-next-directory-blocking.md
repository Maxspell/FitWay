# Bug: Блокировка системной директории `/_next/` в robots.txt и влияние на рендеринг Googlebot

## Описание проблемы

В файле `frontend/src/app/robots.ts` в правилах `disallow` присутствовало правило:
```typescript
disallow: ['/api/', '/*?*_rsc=*', '/_next/'],
```

### Первопричина появления правила
Ранее директива `Disallow: /_next/` была ошибочно добавлена после обнаружения в отчете Google Search Console (раздел «Проскановано – наразі не проіндексовано» / «Crawled - currently not indexed») файла веб-шрифта:
`https://www.fitway.best/_next/static/media/e4af272ccee01ff0-s.p.woff2`

Была сделана ложная гипотеза о том, что Googlebot напрасно расходует краулинговый бюджет на системные файлы сборки Next.js, и директория `/_next/` была закрыта целиком.

---

## Технический анализ и последствия

### 1. Почему файлы стилей и чанков критичны для Googlebot
Современный поисковый робот Googlebot работает на базе актуального Chromium и полностью рендерит страницы сайта (headless browser rendering), вычисляя:
- Фактический макет страницы (Layout) и адаптивность под мобильные устройства (Mobile-Friendly test).
- Метрики Core Web Vitals (включая CLS — сдвиг макета из-за загрузки шрифтов).
- Видимость и доступность контента (CSS-стили, скрытые/раскрытые блоки).

В директории `/_next/` Next.js хранит исключительно публичную клиентскую статику:
- `/_next/static/css/...` — скомпилированные CSS стили сайта.
- `/_next/static/chunks/...` — клиентские JavaScript-бандлы React и компонентов интерактивности.
- `/_next/image?...` — оптимизированные изображения WebP/AVIF.
- `/_next/static/media/...` — подключенные веб-шрифты (`.woff2`).

Блокировка `Disallow: /_next/` приводила к тому, что краулер Google не мог загрузить CSS и JS, видел нестилизованный документ и выставлял предупреждения о заблокированных ресурсах («Blocked Resources») и нарушении мобильной адаптивности.

### 2. Почему статус «Проскановано – наразі не проіндексовано» для `.woff2` — это норма
Когда робот видит в CSS правило `@font-face`, он скачивает файл шрифта для корректного рендеринга страницы. Однако шрифт не является HTML-документом со статьей или страницей каталога. Googlebot логично не включает бинарный шрифт в индекс поисковой выдачи, помечая его статусом «Проскановано – наразі не проіндексовано». Это штатное поведение поисковой системы, не являющееся ошибкой или санкцией.

## Решение

В [robots.ts](file:///d:/Users/doomi/ReactProjects/FitWay/frontend/src/app/robots.ts) исключена директива `/_next/` из массива `disallow`.

```typescript
import { MetadataRoute } from 'next';

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
      disallow: ['/api/', '/*?*_rsc=*'],
    },
    sitemap: 'https://fitway.best/sitemap.xml',
  };
}
```

### Преимущества чистой конфигурации:
1. **Googlebot & Bingbot** имеют беспрепятственный доступ к CSS, JS и шрифтам для точного расчета Core Web Vitals и Mobile-Friendly.
2. Исключен риск конфликта правил `Allow: /_next/static/` и `Disallow: /_next/` у второстепенных поисковых систем и ботов мессенджеров (не все боты корректно поддерживают приоритет `Allow`).
3. Защищены внутренние маршруты API (`/api/`) и предотвращен холостой краулинг служебных полезных нагрузок React Server Components (`/*?*_rsc=*`).

## Дополнительная рекомендация по www-домену

На скриншоте Search Console файл шрифта был зафиксирован по адресу:
`https://www.fitway.best/_next/static/media/...` (с префиксом `www.`).
Каноническим доменом проекта является `https://fitway.best` (без `www`).
Необходимо убедиться, что в конфигурации Nginx настроен постоянный 301-редирект с `www.fitway.best` на `https://fitway.best` для всех путей и ресурсов.
