# FitWay Blog Post Generator

Генерирует SEO-оптимизированные статьи для блога FitWay: готовый JSON для прямого
импорта в Strapi CMS (Content Manager или REST API) + промпты для изображений.

**Схема полей** — см. `references/json-schema.md`.
**SEO-правила** — см. `references/seo-guide.md`.
**Анти-AI правила (Humanizer)** — см. `.agents/skills/humanizer/SKILL.md`. Обязательно к применению для устранения любых маркеров машинной генерации (E-E-A-T и защита от Google AdSense "Low Value Content").
**Примеры тем** — см. `references/topic-ideas.md`.
**Внутренние ссылки (Hub & Spoke: калькуляторы и тренировки)** — см. `references/internal-links.md`. Читай при генерации контента, чтобы обязательно вставлять 1-2 ссылки на интерактивные калькуляторы `/tools/*` и 1-2 ссылки на тренировки.
**Реестр опубликованных статей** — см. `references/existing-posts.md`. Читай ПЕРВЫМ: каждая новая статья должна быть уникальной.

Перед генерацией прочитай reference-файлы.

## Процесс генерации

### Шаг 1 — Определи тему и параметры

Из контекста запроса извлеки или уточни (одним сообщением):

- **Тема**: конкретная или общая
- **Категория** и **автор** (см. справочник ID)
- **Целевая аудитория**: новичок / intermediate / продвинутый
- **Тип статьи**: guide / listicle / how-to / myth-busting / research-based

Если пользователь дал тему, генерируй без лишних уточнений (после проверки уникальности).

### Шаг 1.5 — Проверка уникальности (обязательно, до генерации)

Открой `references/existing-posts.md` и сверь тему:

1. **Slug:** предполагаемый slug не совпадает ни с одним из реестра.
2. **Тема и интент:** primary keyword и search intent не дублируют существующую статью (сравнивай по смыслу, а не только по строке).
3. **Если есть пересечение:** НЕ генерируй статью. Назови пересекающиеся URL, предложи 3 непокрытые темы или уникальных угла и дождись выбора пользователя.
4. **Если тему не указали:** выбирай из `topic-ideas.md` только то, чего нет в реестре.
5. **Уникальный угол** (другой интент, аудитория, ниша) допустим, но объясни в summary, чем статья отличается от соседней.

### Шаг 1.6 — Проверка живой аналитики GSC (Low-Hanging Fruits)

Открой `brain/data/gsc-latest.json` (если файл доступен):
- Проверь массив `low_hanging_fruits` (запросы позиций 10.0–30.0 с показами).
- Если тема статьи пересекается с любым из этих запросов (например, *creatine*, *deficit*, *bands*, *strength*), **обязательно интегрируй точную фразу** в один из подзаголовков `##`/`###` или в блок FAQ!

### Шаг 2 — Генерируй по схеме

Полная схема в `references/json-schema.md`. Критичные правила:

**Структура JSON:**
- `title`: 50–100 символов, содержит primary keyword, **без суффикса `| FitWay`**
- `slug`: lowercase, kebab-case, без стоп-слов, максимум 60 символов
- `content`: Markdown, 1200–1800 слов (считая таблицы и FAQ)
- `excerpt`: 120–160 символов, meta description
- `author`: relation, объект `{ "id": N }` (НЕ строка)
- `reviewedBy`: relation, массив объектов `[{ "id": N }]` (ID рецензента $\neq$ ID автора)
- `category`: relation, объект `{ "id": N }`
- `readTime`: `ceil(wordCount / 200) + " min read"`
- `image`: НЕ включать в JSON, загружается отдельно

**Обязательная структура `content` (7 блоков, в этом порядке):**
1. **Intro** (1 абзац): hook + проблема + что узнает читатель. Primary keyword в первом абзаце
2. **H2-секции** (3–6 штук): основное тело, каждая 150–300 слов
3. **Таблицы** (минимум 1, максимум 3): внутри H2-секций (GFM `|---|---|`)
4. **Practical tips**: списки (ul/ol) с конкретикой, блоки "What to do"
5. **Внутренние ссылки (Hub & Spoke)**: 2–4 ссылки по `references/internal-links.md`:
   - Минимум **1 ссылка на интерактивный калькулятор** FitWay (`/tools/*`)
   - 1–2 ссылки на подходящие тренировки (`/workouts/*`)
6. **Conclusion** (`## Conclusion`): summary + CTA
7. **FAQ** (`## Frequently Asked Questions`): строго последний блок статьи, см. ниже

**Правила таблиц:**
- Markdown pipe-таблицы с заголовком и разделителем `|---|---|`
- 3–6 строк, не более 4 колонок
- Таблица должна нести пользу (сравнение, нормы, трекинг, замены), не декор
- Числа в таблицах должны быть обоснованы; приблизительные помечай `~`
- В `content` переносы строк экранируются как `\n`, кавычки как `\"`
- Без em dash в ячейках

**Правила FAQ:**
- Заголовок раздела: `## Frequently Asked Questions`
- Ровно 3 вопроса, каждый как `### Question?` + ответ абзацем 60–120 слов
- Вопросы строятся по логике People Also Ask: реальные поисковые запросы по теме, с разными search intent
- Ответ начинается с прямого ответа (1 предложение), затем уточнение
- Не повторяй Conclusion, не добавляй CTA в FAQ
- FAQ идёт после Conclusion и ничего не следует за ним

**Правила написания:**
- Язык: **английский**
- Тон: экспертный, но доступный, стиль Healthline / Greatist / Men's Health
- Bold для ключевых фактов и терминов
- НЕ используй em dash `—` (маркер AI-генерации). Замена: запятая, двоеточие, точка, `-`
- Максимум 2–3 внутренних ссылки в теле статьи, без дублей URL

**Научные ссылки (PubMed):**
- Ссылки только прямые на статьи: `https://pubmed.ncbi.nlm.nih.gov/<PMID>/`
- Каждый PMID проверяй через web_search (должна вернуться страница PubMed или источник с этим PMID). Не вставляй PMID по памяти
- Минимум 3 ссылки, каждая один раз, анкор описывает исследование
- Цифры из исследований передавай точно, указывай ограничения (размер выборки, популяция, срок)

**SEO в тексте:**
- Primary keyword: в title, первом абзаце, одном H2, excerpt
- LSI keywords органично (2–4 раза каждый)
- Нет keyword stuffing

### Шаг 2.5 — Анти-AI вычитка по скиллу Humanizer (`.agents/skills/humanizer/SKILL.md`)

Перед финализацией статьи **обязательно** пропусти весь текст через правила скилла `humanizer`. Статья должна читаться так, будто её написал реальный практикующий специалист (диетолог или тренер), а не LLM.

**Критический чеклист паттернов AI к устранению:**
1. **Устранить «Not X but Y» (§1)**: вырежи любые конструкции вида `It's not just about X, it's about Y`, `not only... but...`, `rather than`. Формулируй утверждение прямо и конкретно.
2. **Устранить драматичные однострочные выводы (§2)**: никаких `That is the real win.`, `Consistency is key.`, `Listen to your body.`, `Let that sink in.`. Заменяй на конкретный физиологический или прикладной факт.
3. **Устранить псевдоглубокие фразы (§3)**: вырежи `at its core`, `in reality`, `what really matters`, `the heart of the matter`.
4. **Устранить искусственный разогрев перед мыслью (§4)**: категорически запрещены `Let's dive in`, `let's explore`, `here's what you need to know`, `without further ado`, `Honestly?`, `Look,`. Начинай абзацы сразу с сути.
5. **Устранить споры с воображаемым оппонентом (§5)**: никаких `You might think... but`, `Don't get me wrong`, `To be clear`, `This isn't mainly about`.
6. **Разбить навязчивые триады (§6)**: избегай группировки слов и примеров строго по три штуки (`energy, endurance, and strength`). Варьируй длину и структуру предложений.
7. **Полный запрет Em Dash и En Dash (§8)**: ни одного `—`, `–` или ` -- ` во всем тексте. Заменяй на точки, запятые, двоеточия или скобки.
8. **Тотальный блэклист заезженных AI-слов (§12)**:
   - Запрещены: `delve`, `delving`, `crucial`, `pivotal`, `deep dive`, `testament`, `tapestry`, `landscape`, `vibrant`, `robust`, `underscore`, `underscores`, `highlight`, `intricate`, `meticulously`, `quietly`, `foster`, `enhance`, `showcase`, `interplay`, `valuable`, `game-changer`, `holistic`, `seamlessly`.
   - Заменяй простыми прямыми глаголами и существительными (`is`, `has`, `shows`, `builds`, `needs`, `helps`).
9. **Устранить раздутую значимость (§13)**: никаких `stands as a testament`, `plays a pivotal role`, `marks a crucial turning point`, `the future looks bright`.
10. **Устранить поверхностные причастные хвосты на -ing (§15)**: вырежи навязчивые `highlighting the importance of...`, `ensuring optimal recovery`, `reflecting a commitment to...`.
11. **Устранить рекламный пафос (§16)**: убрать `breathtaking`, `stunning`, `revolutionary`, `groundbreaking`, `game-changing`.
12. **Прямое цитирование вместо размытого авторитета (§17)**: вместо `experts agree` или `studies show` — ссылайся на точный контекст исследования с прямым URL на PubMed или пиши от лица автора (Sarah Johnson / Mike Chen).
13. **Использовать простые глаголы (§18)**: вместо `serves as a protein source` или `functions as a stimulant` пиши `is a protein source` или `stimulates the central nervous system`.
14. **Устранить шаблонный полужирный шрифт в списках (§19)**: не оформляй каждый буллет как `- **Heading:** Description`. Делай естественные списки или переводи в связную прозу.
15. **Заголовки в Sentence Case без эмодзи (§20)**: используй sentence case (`## How to calculate your calorie deficit`, а не `## How To Calculate Your Calorie Deficit`). Никаких эмодзи в заголовках.
16. **Нулевой остаточный след чатбота (§22)**: никаких `In this comprehensive guide...`, `Certainly!`, `I hope this helps!`.
17. **Не дублировать H2 в первом предложении раздела (§24)**: первое предложение после заголовка не должно повторять заголовок другими словами.

### Шаг 4 — Автоматический импорт в Strapi (Production Draft)

После успешной генерации и валидации агент выполняет следующие шаги **автоматически**:

1. **Сохранение в staging-файл `backend/scripts/posts.json`**:
   - Запиши сгенерированный объект статьи в `backend/scripts/posts.json` в виде массива `[ { ... } ]`.
2. **Отправка в Strapi**:
   - Выполни команду импорта в продакшн Strapi:
     ```bash
     node backend/scripts/push-post.js backend/scripts/posts.json --prod
     ```
   - Статья загружается в Strapi в статусе **DRAFT**. Фотографии (Hero и инфографики) пользователь добавляет вручную через админку Strapi перед публикацией.
3. **Регистрация в реестре**:
   - Сразу добавь новый slug и URL в `references/existing-posts.md` и обнови счётчик общего числа статей.

## Visual Content Suggestions (вне JSON)

Изображения в JSON не входят. После summary выдай промпты, готовые к вставке в AI-генераторы изображений (Midjourney v6, Ideogram, Flux, DALL-E 3) или передаче дизайнеру.

**Критическое правило языка и стиля:**
- Все промпты и все тексты внутри визуала генерируются **строго на английском языке**.
- Инфографики должны **строго воспроизводить фирменный UI/UX дизайн сайта FitWay** (dark-mode health-tech aesthetic).
- **Без em dash `—`** в текстах на изображениях и в промптах (используй дефис `-`, двоеточие `:` или запятую).

  - **Typography**: Чистый белый `#FFFFFF` для главных заголовков и цифр; мягкий серебристый/сланцевый `#94A3B8` / `#CBD5E1` для описаний, подписей и единиц измерения.
- **Стилистика и композиция (Aesthetic & Layout)**:
  - Премиальный **dark-mode sports-science / health-tech UI dashboard** (в стилистике интерфейса FitWay, Whoop, Apple Fitness, Strava).

  - Современный гротескный шрифт без засечек (Inter, SF Pro Display, Montserrat style), четкая типографическая иерархия и высокая читаемость данных.
- **Размер**: 1080×1080 (Square 1:1, `--ar 1:1`) или 1080×1350 (Portrait 4:5, `--ar 4:5`).

#### Формат вывода каждой инфографики:

1. **Title & Concept** (краткое пояснение на русском: какую часть статьи иллюстрирует).
2. **Ready-to-use Prompt (English)**: готовый для генератора изображений промпт в code block на английском языке, включающий точные параметры соотношения сторон, цветовую палитру FitWay (`#1B2B3B`, `#243447`, `#FF8C00`, `#FFFFFF`), композицию карточек и точные надписи в кавычках.
3. **Structured Content Specification**:
   - `Header`: Заголовок инфографики на английском.
   - `Cards / Steps / Data Points`: Точные названия блоков, цифры и краткие описания (строго из текста статьи).
   - `Bottom Callout`: Итоговый вывод/инсайт в оранжевом акцентном блоке.

> **Важно:** Все цифры и значения должны быть на 100% согласованы со статьей. Никаких выдуманных данных. Никаких белых фонов или мультяшных клипартов.

---

## Ограничения

- НЕ добавлять поля, которых нет в Strapi-схеме (разрешены: title, slug, content, excerpt, author, category, readTime)
- НЕ включать `image`/`media` в JSON
- НЕ ставить `author` строкой ("FitWay Team" больше не используется)
- НЕ давать медицинские обещания и гарантии результата
- НЕ использовать em dash `—` нигде в тексте
- НЕ делать `slug` длиннее 60 символов
- НЕ писать `excerpt` длиннее 160 символов
- НЕ ставить ничего после FAQ
- НЕ генерировать статью, если её slug, тема или интент уже есть в `existing-posts.md`
- НЕ вставлять PMID без проверки
