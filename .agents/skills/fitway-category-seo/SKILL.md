# FitWay Category SEO

Пишет тексты для страниц категорий блога FitWay так, чтобы страница была хабом по теме,
а не голым списком карточек. Весь вывод на английском, пояснения пользователю на русском.

**Карта категорий, ключи, связи** - `references/category-map.md`.
**Правила стиля (анти-AI слой)** - `references/style-rules.md`.
**Формат вывода (поля Strapi category) и внедрение в Next.js** - `references/output-schema.md`.
**Валидные URL тренировок** - `references/workout-links.md` из скилла `fitway-blog-post-generator`.
Не придумывай URL. Если файла нет в контексте, используй только URL, которые видишь на живых страницах.

Перед генерацией прочитай все три файла из `references/` этого скилла.

---

## Зачем это нужно

На момент создания скилла страницы категорий содержат только H1 и список карточек, без
уникального текста. Шаблонный meta description, общий meta keywords, title с задвоенным
брендом ("Nutrition Articles | FitWay | FitWay"). Для Google это тонкие страницы-листинги,
для AdSense один из сигналов low value content. Проверяй текущее состояние при каждом
запуске, оно могло измениться.

---

## Принципы

1. **Категория это хаб.** Запрос пользователя информационный и исследовательский. Текст помогает
   выбрать нужную статью и понять структуру темы. Он не пересказывает статьи.
2. **Широкий запрос у категории, узкий у статьи.** Категория целится в общий запрос
   ("muscle building tips"), статьи в конкретные ("how much protein to build muscle").
   Не бери primary keyword из заголовка отдельной статьи, иначе каннибализация.
3. **Текст привязан к реальным статьям.** Каждый абзац опирается на статьи, которые сейчас
   есть в категории. Это главный фильтр против шаблонности: текст нельзя перенести в другую
   категорию заменой одного слова.
4. **Короткий intro сверху, основной текст под листингом.** Листинг остаётся первым экраном.
5. **Один primary keyword + 3-6 вторичных.** Вторичные берутся из реальных заголовков и тем
   статей категории, а не из головы.
6. **YMYL.** Никаких обещаний результата, диагнозов, дозировок, медицинских советов.
   Не приписывай тексту экспертную проверку, которой нет. Не придумывай статистику.
7. **Уникальность между категориями.** Шесть текстов не должны делить предложения, структуру
   H2 и формулировки. Углы разные, см. `category-map.md`.

## Процесс

### Шаг 1 - Входные данные

Нужна категория (slug или URL). Если категория названа, больше ничего не спрашивай.
Режим "все категории": обрабатывай по одной, сверяя уникальность с уже написанными.

### Шаг 2 - Живая страница

`web_fetch` с `html_extraction_method: markdown` на `https://fitway.best/blog/category/{slug}`.
Забери: текущие title и meta description, список статей (заголовок, URL, excerpt, автор),
наличие пагинации. Если страница недоступна, попроси список статей у пользователя, не пиши вслепую.

### Шаг 3 - План

- Сгруппируй статьи категории в 2-4 тематических блока.
- Выбери primary keyword из `category-map.md` (это гипотеза, не данные о частотности)
  и вторичные из реальных тем статей.
- Выбери угол категории и связанные категории из `category-map.md`.
- Подбери 1-2 релевантные тренировки из `workout-links.md`.
- Если в категории меньше 4 статей, сократи основной текст до нижней границы и скажи об этом.
  Длинный текст над тремя статьями выглядит как SEO-простыня.

### Шаг 4 - Написание

Структура и объёмы (поля коллекции `category` в Strapi):

| Поле Strapi | Объём | Требования |
|-------------|-------|------------|
| `title` | 2-6 слов | Это H1 страницы. Primary keyword в естественной форме. Не "X Articles" |
| `intro` | 40-70 слов | Тип `text`, чистый текст без Markdown и ссылок. Над листингом. Primary keyword в первом предложении. Что здесь найдёт читатель |
| `text` | 350-600 слов + FAQ | Тип `richtext`, Markdown. Под листингом. Начинается с H2 (H1 выводит фронтенд из `title`). 3-4 H2 по тематическим блокам, 1 H2 "кому и с чего начать", затем H2 `Frequently Asked Questions` с 3-4 вопросами как H3 и ответом 35-60 слов. Слова FAQ в лимит 600 не входят |
| `metaTitle` | до 60 символов | Без бренда, если шаблон Next.js добавляет его сам (см. `output-schema.md`) |
| `metaDescription` | 120-160 символов | Тип `text`. Primary keyword, конкретная польза, без кликбейта |
| `name`, `slug` | - | Выводятся для справки. Если категория уже создана в Strapi, не менять |

Правила текста:
- В `text` не использовать H1, таблицы, HTML, блоки кода. Только H2/H3, абзацы, списки, ссылки Markdown.
- Каждый тематический H2 называет конкретные статьи и объясняет, какой вопрос каждая закрывает.
- Заголовки H2 пиши как описание содержания, не как шаблон. Запрещено повторять одну и ту же
  схему H2 во всех категориях.
- Числа только если они безопасны: размер категории, диапазоны, которые есть в статьях
  как рекомендации. Статистику из excerpts ("up to 80% of athletes...") не переноси.
- Правила из `style-rules.md` обязательны. Em dash `—` запрещён везде.

### Шаг 5 - Ссылки

Ссылки ставятся только в поле `text`, как Markdown, относительными URL. Лимиты для хаб-страницы (это сознательное отличие от правила 2-3 ссылки в теле статьи,
которое действует для постов):
- Ссылки на статьи этой же категории: до 6, каждая уникальна, анкор описывает содержание статьи.
- **Ссылки на интерактивные калькуляторы (`/tools/*`)**: 1–2 обязательные ссылки согласно `references/category-map.md` (например, Nutrition $\rightarrow$ `/tools/macro-calculator` и `/tools/calorie-calculator`, Muscle Building $\rightarrow$ `/tools/one-rep-max-calculator`).
- Ссылки на тренировки: 1-2.
- Ссылки на соседние категории: 1-2, чистый URL `/blog/category/{slug}`.
- Без дублей целевых URL внутри страницы. Анкор совпадает по смыслу с назначением.
- Никаких URL с `?category=` и фильтрами.
- Не ссылайся на саму категорию.

### Шаг 6 - Валидация

- [ ] primary keyword есть в `metaTitle`, `metaDescription`, `title`, первом предложении `intro`, одном H2 в `text`
- [ ] primary keyword встречается в тексте не более 4 раз, без стаффинга
- [ ] `metaTitle` до 60 символов, `metaDescription` 120-160
- [ ] каждая ссылка на статью взята с живой страницы, URL проверен по списку из шага 2
- [ ] нет em dash `—` нигде, включая FAQ
- [ ] нет статистики и цифр "результата", нет обещаний, нет дозировок
- [ ] нет фраз из блэклиста `style-rules.md`
- [ ] swap test: ни один абзац не подходит другой категории без переписывания
- [ ] FAQ внутри `text` оформлен как H2 + H3 с ответами, без отдельного поля
- [ ] `intro` без Markdown и ссылок, `text` без H1
- [ ] нет совпадающих предложений с уже написанными категориями
- [ ] ни одно поле не содержит лишней обёртки, кавычек или пояснений

### Шаг 7 - Вывод

Не JSON. Формат вывода строго по `output-schema.md`: каждое поле Strapi отдельным блоком с
названием поля и содержимым в code block, чтобы копировать одним кликом. Поле `text` в блоке
```markdown```. После блоков 3-4 строки на русском: категория, primary keyword, объём `intro` и
`text`, какие статьи привязаны, что сверить вручную (пагинация, актуальность списка статей).

---

## Ограничения

- НЕ писать длиннее 600 слов основного текста, это не статья, а хаб-описание
- НЕ копировать excerpts и заголовки статей целыми блоками
- НЕ придумывать авторов, рецензентов, источники, исследования, цифры
- НЕ указывать медицинскую проверку, если её нет
- НЕ добавлять в вывод поля, которых нет в схеме коллекции `category`
- НЕ выводить JSON, JSON-LD и служебные структуры: только текстовые поля для вставки
- НЕ использовать em dash `—` нигде в тексте
